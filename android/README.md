# 多机接收 · 安卓升级版 0.2

独立原生 Android 接收端，在 android-receiver 分支开发。原 clipboard 网页与 GitHub Pages 保持原样。

## 使用

1. 安装 C1Clip-Android-0.2.0.apk。0.2 使用独立应用 ID cn.c1clip.receiver.upgrade，可与旧测试版并存。
2. 打开“连接与权限设置”，粘贴原电脑端对应手机的配对链接，保存并接收。停止该手机旧 APP 或网页的接收，避免同一配对重复连接。
3. 在系统设置开启辅助填写权限、通知和所需后台联网权限。
4. 接收资料后点击“猫眼”。首次选择手机上安装的猫眼，以后直接启动。

## 本次更新

- 一键按顺序填写全部人员，勾选实名说明、点击确定；先核对列表保存结果，再添加下一人。
- 保存进度与提交等待状态。中断后优先检查上次结果；不把点击成功当作保存成功。
- 明确的网络或添加失败最多尝试 6 次，重试间隔至少 1.2 秒。结果不明、资料错误、验证或频率提示会暂停；可在设置中核对后解除结果不明状态。
- 用页面变化触发下一步，减少固定等待。没有可访问控件或页面无法唯一识别时暂停。
- 蓝白卡片界面，主入口只有“猫眼”；配对、权限、其他应用入口和剪贴板工具折叠收纳。
- 可选择全部保存完成后打开一个已安装应用，停留 1 / 2 / 3 / 5 秒，再返回猫眼。默认关闭，核对实际前台应用后报告结果。
- 保留后台接收、独立逐条复制、输入法历史手动确认、清空资料等功能。

## 边界

后台接收与前台填写分开；填写需保持解锁。系统强停、断网或省电限制可能中断接收。大麦和票星球目前仅提供启动入口。辅助流程只管理观演人信息，不下单、支付或处理验证码。真实猫眼控件与设备适配需实机验证，模拟器启动检查不代表第三方 APP 全流程验收。

0.1 使用临时测试签名，0.2 改用独立应用 ID，并在交付时使用持久私有签名。私钥保存在仓库之外。CI 产物是临时签名调试包，不能直接用于覆盖已交付的固定签名包。

## 构建

Java 17、SDK 35、Gradle 8.13，最低 Android 8：

```sh
cd android
gradle testDebugUnitTest assembleDebug
```

GitHub Actions 构建并执行协议、提交状态单元测试，以及 Android 14 模拟器启动检查。构建产物保留 30 天，源码可随时重新构建。
