# 多机接收 · 安卓升级版（0.1 测试版）

本目录是独立原生 Android 接收端。原 `clipboard/` 网页及 GitHub Pages 不做任何修改；安卓端在 `android-receiver` 分支开发。最低 Android 8，面向 Android 15 编译；小米/红米真机适配需安装后验证。

## 安装与配对

1. 安装构建产物 `app-debug.apk`（应用名：多机接收·升级版）。这是测试签名包，不能当作已完成真机验收的正式版。
2. 原电脑端选择对应手机 → 配对 → 复制连接链接，粘贴到 APP 后点“保存配对并接收”。不用重新建手机或分组。
3. 这部手机关闭原接收网页，避免两个接收端同时使用同一设备配对；其他手机可继续使用网页。
4. 允许通知，点击“允许持续后台联网”，在系统弹窗批准电池优化豁免。根据小米系统版本检查后台自启动、无限制省电等选项。
5. 点击“开始后台接收”。通知栏保留接收状态与停止按钮。电脑网页仍需保持打开；电脑离线时没有服务器离线消息邮箱。

## 已实现

- 原生 MQTT over WSS 双节点连接、AES-GCM 协议兼容、断线重连、应用层心跳。
- 安卓 `remoteMessaging` 前台服务负责跨设备文字消息接收；通知可见，用户可以停止。接收时使用部分唤醒锁，停止时释放。电池优化豁免由用户明确批准；增加耗电，不能承诺系统强停或断网后仍在线。
- 配对与最新内容使用 Android Keystore 加密保存，禁用系统备份。正文在本机到期清理；12 小时过期后不可填写。只接收更新的消息，旧消息不能覆盖新内容。
- 在 APP 前台按 1500 毫秒逐条复制；离开前台、失去焦点、新内容到达都会中止旧复制任务。输入法历史成功需要真机检查并手动确认，不能从系统复制 API 的返回值推断。
- 从用户所选的已安装应用启动猫眼、大麦、票星球。无硬编码包名或商店跳转。每次由手机端用户点击启动，不在锁屏时强行拉起页面。
- 猫眼可从四张参考页面中的任一已支持页面开始：“我的 → 观演人信息 → 添加/修改 → 添加观演人信息”。使用可访问控件的文字、描述与输入框提示定位，未实现 OCR，也不进行固定坐标盲点。
- 每次填写本机选中的一名人员。填完核验控件值并停止，用户自行查看实名说明、勾选协议、点击确定。多人需逐人核对保存后回 APP 选下一人。
- 无障碍读取限制到当前主动选定的目标应用，只在手动启动任务期间操作，不上传或记录页面内容。不匹配、按钮不响应、资料变更、锁屏、超时均停止。

## 当前边界与真机验收

- 截图无法提供实际 `resource-id`、可访问控件树、焦点和输入行为。本版是依据截图文字的候选适配，不能宣称已经在猫眼真机跑通。若猫眼把页面绘制为不可访问图层，则会停止并提示手动处理，需在真机提供控件信息后适配。
- 大麦、票星球只有启动入口，尚未收到它们的填写页面截图，因此没有自动填写流程。
- 测试签名 APK 的后续更新需要保持同一签名；本 CI 使用临时调试签名，未来正式升级前需配置持久私有签名密钥。不要在仓库公开签名私钥。不要为升级而直接清除应用数据；先保存原配对链接。
- 本版不提供无人值守下单、支付、删改已有观演人、自动协议确认或验证码操作。
- 无后台自动打开目标应用；后台只接收资料。前台辅助填写需要用户开启系统无障碍权限并解锁。

安装后请先用一台手机、获得授权的资料确认三件事：电脑显示在线；息屏一段时间仍能接收（回 APP 看最新内容与电脑回执）；猫眼四步能正确定位并填完停止。不要直接在 29 台手机一起启用未经真机确认的流程。

## 构建

Java 17、Android SDK 35、Gradle 8.13：

```sh
cd android
gradle testDebugUnitTest assembleDebug
```

GitHub Actions 在 `android-receiver` 分支构建，产物 `c1clip-android-test`，有效期 30 天。保留源代码可随时重新构建。未修改现有网页上线流程。
