# 多机剪贴板

入口：https://c1x3a.github.io/1221/clipboard/

电脑可以新增、删除和重命名任意数量的手机，并建立自定义快捷分组。发送时可手动选择、全选或一键选择整组；每行作为独立字符串传输。在“各手机不同内容”模式中，发送框留空的手机会被跳过，不影响其他有内容的手机。手机配对后收到批次，点击一次按间隔逐条写入剪贴板。默认标准 Clipboard API、1500 ms；该组合已由用户在一部标记为“小米 12 Pro · 1”的 Android 14 微信 WebView 上验证，四条独立出现在输入法历史。其他手机与浏览器仍需真机验证。

电脑端还提供本地“姓名＋身份证”提取：粘贴长文本后，识别 18 位或 15 位身份证格式，并依据姓名标签、同行或相邻关系生成可编辑、可勾选的核对表。选中人员按“姓名一条、身份证一条”的顺序填入发送框；多人结果超过 20 条时自动拆成多批。提取不联网，也不核验身份证真伪。

## 使用

1. 电脑打开入口，批量添加并命名手机；保留的旧版四部手机配对不会被覆盖。
2. 升级到 MQTT 版本后，点击每部手机的“配对”，让对应手机重新扫码或打开专用链接；电脑显示“在线”。
3. 可将任意多部手机存为自定义分组；点击分组名即可一次选中其成员。
4. 直接按行填写，或粘贴整段文字提取姓名和身份证；核对后填入统一内容或指定手机的单独内容。
5. 点击发送。超过 20 条的内容自动分批，每批在手机端独立处理。
6. 手机收到后点输入框唤起键盘，再点“一键逐条复制”；过程中保持页面在前台。
7. 在输入法剪贴板查看独立记录，确认后可点“历史中已全部出现”。

添加桌面：在手机浏览器中打开同一个配对链接，使用浏览器的安装或添加到主屏幕功能。微信 WebView 内不能保证提供此功能。

## 传输与存储边界

- 静态页面由 GitHub Pages 提供，设备消息通过 MQTT over WSS 中继，不再依赖 PeerJS、WebRTC、STUN 或路由器端口转发。默认同时连接 EMQX 公共多区域节点 `broker.emqx.io` 和备用接入，消息发往所有当前可用节点，任一共同节点可用即可传输；也可在“连接设置”中换成自己的兼容 WSS 服务。公共节点免费、无需账号，但由第三方维护且没有本项目能够承诺的可用性或容量保证。
- 电脑和手机需要同时保持页面打开。未确认接收的批次保存在当前电脑标签页，在线后重发；刷新可恢复当前标签页 sessionStorage，关闭标签页不能保证恢复。没有云端离线收件箱。
- 配对凭据、设备名称和分组保存在当前浏览器 localStorage；朋友在另一浏览器使用时拥有独立列表。临时草稿、发件记录、收件内容保存在本标签页 sessionStorage，批次最多保留 12 小时。浏览器清理数据会丢失这些本机状态。到期清理发生在页面活动期间；不控制输入法自身历史期限。
- 每部手机使用独立随机 256 位密钥，配对信息在 URL fragment 中，不随页面 HTTP 请求发送。消息使用 AES-GCM 加密且带连接会话随机值，MQTT 服务只能看到随机主题和加密数据，无法读取正文。
- 控制台与设备 ID 用于组成随机 MQTT 主题，不作为认证。只有持有对应设备密钥的手机才能解密批次或生成有效回执。配对链接是访问凭据，不应公开分享。
- 批次保留顺序、重复条目、空格和标点；跳过空行。不合并正文为单条复制内容。收到重复批次 ID 时只回执，不追加批次。
- 每批最多 20 条，电脑端一次最多准备 240 条，并按顺序拆成不超过 12 批。身份证原文及提取结果均只在当前页面中处理；只有点击发送后，选中的条目才会进入对应手机的数据通道。
- 不在网页后台自动写剪贴板；失去焦点或停止时中断后续写入。复制回执与输入法历史确认严格分开，后者只能由用户检查确认。

## 文件

`core.mjs`：条目验证、配对编码、加密、逐条复制。
`manage.mjs`：设备增删改名、旧数据迁移和分组成员管理。
`extract.mjs`：姓名与身份证的本地匹配及独立条目生成。
`app.mjs`：界面、连接认证、重连、队列与回执。
`vendor/`：随仓库提供 MQTT.js 和二维码依赖，避免页面加载时依赖第三方 CDN。
`sw.js` / `manifest.webmanifest`：离线页面资源缓存与桌面安装支持。

验证范围：代码语法、四条独立写入与失败中止、消息加密及篡改拒绝、不同设备密钥隔离、批次验证；没有冒充对四部实体手机做过完整连接测试。
