# 多机剪贴板

入口：https://c1x3a.github.io/1221/clipboard/

电脑选择四部手机之一或多部，按行填写并发送；每行作为独立字符串传输。手机配对后收到批次，点击一次按间隔逐条写入剪贴板。默认标准 Clipboard API、1500 ms；该组合已由用户在一部标记为“小米 12 Pro · 1”的 Android 14 微信 WebView 上验证，四条独立出现在输入法历史。其他手机与浏览器仍需真机验证。

## 使用

1. 电脑打开入口，点击每部手机的“配对”。
2. 对应手机扫码或打开其专用链接；电脑显示“在线”。
3. 电脑勾选手机；选择统一内容或分别填写；每行一条，点击发送。
4. 手机收到后点输入框唤起键盘，再点“一键逐条复制”；过程中保持页面在前台。
5. 在输入法剪贴板查看独立记录，确认后可点“历史中已全部出现”。

添加桌面：在手机浏览器中打开同一个配对链接，使用浏览器的安装或添加到主屏幕功能。微信 WebView 内不能保证提供此功能。

## 传输与存储边界

- 静态页面由 GitHub Pages 提供，PeerJS 1.5.5 公共服务负责连接信令，WebRTC 数据通道负责文本传输。公网信令服务和 STUN 的可达性、NAT 类型会影响连接；没有配置付费或私有 TURN 中继，不能保证所有移动网络均可直连。
- 电脑和手机需要同时保持页面打开。未确认接收的批次保存在当前电脑标签页，在线后重发；刷新可恢复当前标签页 sessionStorage，关闭标签页不能保证恢复。没有云端离线收件箱。
- 配对凭据和设备设置保存在当前浏览器 localStorage；临时草稿、发件记录、收件内容保存在本标签页 sessionStorage，批次最多保留 12 小时。浏览器清理数据会丢失这些本机状态。到期清理发生在页面活动期间；不控制输入法自身历史期限。
- 每部手机使用独立随机 256 位密钥，配对信息在 URL fragment 中，不随页面 HTTP 请求发送。消息使用 AES-GCM 加密且带连接会话随机值，并经过双方握手确认。信令 metadata 只含设备标识，不含配对密钥或正文。
- 稳定控制台 Peer ID 仅用于发现；不作为认证。陌生连接必须通过对应设备密钥验证才能接收批次或上报状态。配对链接是访问凭据，不应公开分享。
- 批次保留顺序、重复条目、空格和标点；跳过空行。不合并正文为单条复制内容。收到重复批次 ID 时只回执，不追加批次。
- 不在网页后台自动写剪贴板；失去焦点或停止时中断后续写入。复制回执与输入法历史确认严格分开，后者只能由用户检查确认。

## 文件

`core.mjs`：条目验证、配对编码、加密、逐条复制。
`app.mjs`：界面、连接认证、重连、队列与回执。
`vendor/`：随仓库提供的依赖，避免页面加载时依赖第三方 CDN。
`sw.js` / `manifest.webmanifest`：离线页面资源缓存与桌面安装支持。

验证范围：代码语法、四条独立写入与失败中止、消息加密及篡改拒绝、不同设备密钥隔离、批次验证；没有冒充对四部实体手机做过完整连接测试。
